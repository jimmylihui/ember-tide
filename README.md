# 烬潮 · Ember & Tide

原创开源 PvP 卡牌游戏的可玩最小版本。独立实现规则与美术，无第三方运行时依赖。代码、卡牌文字和程序绘制的 SVG 插画均使用 MIT 许可。

## 运行

需要 Node.js 22.13 或更新版本（本地持久化使用 Node 内置 SQLite）。

```sh
git clone https://github.com/jimmylihui/ember-tide.git
cd ember-tide
npm run build
npm start
```

打开 http://localhost:4173 。无需安装依赖。默认监听所有网卡；同一局域网的另一台设备可访问 `http://主机局域网IP:4173`，创建或加入房间。设置 `PORT` 可更改端口。房间数据库保存在 `.data/rooms.sqlite`，不包含在源码包中。

- **同屏双人**：每次行动权交接后遮住手牌，下一位玩家点击“我已就位”继续。
- **联机房间**：创建者使用赤烬议会，加入者使用潮汐守望。将 8 位房间码告诉另一位玩家，对方在同一个服务上加入。每个标签页保存自己的座位凭证；刷新后点击“重连联机房间”。请用不同标签页或设备操作两个座位。
- **托管试玩**：Sites 默认仅拥有者可访问；朋友需要获准访问托管站点，或使用上述局域网 / 自行部署版本。房间码只用于加入游戏，不会改变站点访问权限。

## MVP 内容

20 种原创卡牌，每方 10 种、每种 3 张，形成两套 30 张固定套牌。支持完整胜负、20 生命核心、交替行动、每轮交替的进攻令牌、最多 6 个单位、多单位进攻及逐一阻挡、3 点法术法力、慢速 / 快速 / 瞬发、后进先出响应链、先攻 / 穿透 / 再生，以及按阵营进度升级的两位英雄。站内“玩法指南”介绍完整操作；“卡牌图鉴”展示全部卡牌。

赤烬议会侧重先攻、直接伤害与穿透；潮汐守望侧重恢复、再生和高生命单位。插画为原创几何 SVG，而非成品级角色绘画。

最小版本暂不含起手换牌、自组套牌、排位、观战、行动计时器、复杂关键词和动画。冻结在整轮内将攻击力保持为 0，期间攻击力增益也被压制。暂时生命增益消失时，将当前生命截断至新上限。响应链全部结算后，进攻令牌持有方先行动；战斗结束后由防守方行动。这些是本原型明确采用的简化规则，非原游戏的逐项复刻。

## 验证

GitHub Actions 会在 push 和 pull request 时使用 Node.js 22 自动构建、验证产物并运行测试。

```sh
npm run build
npm run validate
npm test
```

包含规则单元测试、100 场可复现的随机对局、房间 API 的隐藏信息检查、并发加入与并发操作检查。联机端以服务端为准，客户端只提交操作；数据库使用版本比较更新，防止重复提交和覆盖。对手手牌与牌库顺序不会返回给客户端。

## 项目结构

- `src/engine.js`：无 UI、网络或存储依赖的规则引擎；输入状态不原地修改。
- `src/app.js`：牌桌、卡牌 SVG 插画、同屏和联机交互。
- `src/style.css`、`src/index.html`：响应式界面。
- `worker/index.js`：服务端权威房间 API，使用 D1 接口。
- `drizzle/`：托管数据库迁移。
- `scripts/serve.mjs`：Node HTTP 服务及 SQLite 适配器。
- `scripts/build.mjs`：将引擎、UI 和 API 合成单文件 Worker。
- `tests/`：规则与服务端集成测试。

## 自行部署

本地 Node 服务可以部署在支持 Node 22+ 且提供持久化磁盘的主机。Cloudflare Worker 部署使用构建输出 `dist/server/index.js`，绑定名为 `DB` 的 D1 数据库，并先应用 `drizzle/0000_rooms.sql`。Sites 托管由 `.openai/hosting.json` 声明所需资源。仓库只包含通用资源配置，不包含任何已部署项目的标识或凭证；自行部署时，请在自己的账户中创建项目及数据库，并连接自己的部署资源。

用于正式公开服务前，需要补充请求限流、房间过期清理、玩家账户或更完善的防滥用措施。目前房间不自动过期，没有匹配系统，不适合直接运营大规模公开服务。
