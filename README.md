# Legends of Runeterra · 基础卡池 PvP 复现原型

基于原版 **Legends of Runeterra（符文大地传说）** 卡牌与插画的非官方开源 PvP 原型。项目使用独立编写的 JavaScript 规则引擎，支持同屏双人、联机房间与自组套牌，无第三方运行时依赖。

卡牌目录包括 Foundations（`Set1`）的全部 **318 张可收集卡牌**，以及升级形态、技能和其他衍生卡，共 **419 条记录**。名称、规则文字和官方卡面采用繁体中文，同时保留英文名称。数据固定为 Riot Data Dragon **`7_10_0`**，因此使用该版本的数值与文字，并非开服时的历史平衡。

**318 张可收集卡牌均已接入可执行规则，可用于组牌与对战，其中包括 24 位英雄。** 逐地区卡牌清单和规则说明见 [COVERAGE.md](COVERAGE.md)。这是基础卡池规则引擎与 PvP 界面的复现；规则注册覆盖完整，并不等于所有交互都已逐项通过官方客户端一致性认证。

## 本地运行

需要 **Node.js 22.13 或更新版本**。本地房间持久化使用 Node 内置 SQLite，无需安装 npm 依赖。

```sh
git clone https://github.com/jimmylihui/ember-tide.git
cd ember-tide
git switch lor-foundations
npm run build
npm start
```

打开 [http://localhost:4173](http://localhost:4173)。服务默认监听所有网卡；同一局域网的另一台设备可以访问 `http://主机局域网IP:4173`。可用 `PORT=4174 npm start` 更换端口。房间数据库保存在 `.data/rooms.sqlite`，不包含在源码仓库中。

## 开始一场对局

1. 选择预组套牌，或从“组建套牌”中保存自组套牌。套牌必须为 **40 张**，同名最多 **3 张**、英雄最多 **6 张**、最多 **2 个地区**。自组套牌保存在当前浏览器。
2. **同屏双人**：为双方选择套牌。行动权交接时手牌会被遮住，下一位玩家点击“我已就位”继续。
3. **联机房间**：创建者和加入者各自选择自己的套牌。创建者将 **8 位房间码**交给另一位玩家，对方在同一服务中加入。请使用不同标签页或设备操作两个座位；各标签页保存自己的座位凭证，可通过“重新连线”恢复。
4. 双方各获 **4 张起手牌**，选择要替换的牌后确认。换牌完成后进入第 1 轮，双方各抽 1 张牌。

两套预组分别是“蓋倫与布郎姆 · 钢铁与寒冰”和“達瑞斯与吉茵珂絲 · 侵略与火力”。具体卡表由 `src/cards.js` 的 `PRESETS` 导出维护。

托管试玩仍沿用 [项目试玩站](https://ember-tide-duel.bloomy-wave-2276.chatgpt.site)。Sites 的站点访问权限与游戏房间码独立；房间码不改变站点的访问权限。也可以使用上述局域网服务或自行部署。

## 已接入的玩法

- 20 生命主堡、交替行动、每轮抽牌与法力增长、最多 3 点法术法力、最多 6 个场上单位及 10 张手牌。
- 起手换牌、多单位进攻与格挡、挑战者指定格挡、进攻令牌与 Rally，以及满场时选择替换己方单位。
- 慢速、快速、疾速及专注法术，响应链与技能结算；多目标、效果选择、主动选择弃牌与献祭，三选一卡牌展示。
- 快速攻击、双重攻击、碾压、挑战者、隐密、威吓、坚忍、屏障、吸血、再生、瞬逝等关键字，以及对应卡牌的状态与回合效果。
- 24 位英雄各自的升级条件、升级形态与英雄法术转换；生成牌、法术复制、弃牌触发、逐张牌附着的剧毒膨菇与抽牌触发伤害。
- 牌库检索与移动、精确复制与普通复制、复活与下轮复活、召唤进攻中的单位、捕获与释放、临时控制，以及作用于各处同名牌的增益。
- 全卡图鉴、繁中与英文名称搜索、地区与实现状态筛选、关联卡牌查看，以及原版完整卡面。

随机生成、展示与相关候选池限定在本项目收录的 Foundations 卡池中，不包含后续扩展。卡牌数值与规则文字采用固定 `7_10_0` 数据；运行时实现状态由 [COVERAGE.md](COVERAGE.md) 与图鉴显示。

## 交互与动画

- 手持卡牌可拖到己方战场；需要目标、弃牌、献祭或效果选择的卡牌会保留确认步骤。场上单位拖向战线可选为攻击者，防守单位拖到战线可分配格挡，均需确认攻防。
- 联机状态依据服务端公开事件播放出牌、法术、攻防、伤害、治疗、护盾、离场、升级与回合演出。动画不改变规则结果，重新连接和重复轮询不会重放旧动作。
- 同屏模式先从当前玩家视角播放已公开的动作，再遮住手牌并交接设备；对手的隐藏手牌不会被动画提前展示。
- 顶部「动画」按钮可切换完整或简化反馈，默认遵从系统的减少动态效果偏好。鼠标点击操作始终可用，触屏手牌保留横向滚动，纵向拖动或长按开始拖牌。
- 当前英雄升级使用原版插画配合原创网页演出，没有嵌入官方客户端的专属升级视频、语音或音效。

## 当前边界

- 引擎已有单卡与交互测试，但尚未对所有规则组合、结算顺序与异常状态逐项对照官方客户端。卡牌的“已实现”标记表示存在可执行规则。
- 本项目范围为基础卡池 PvP，不包含后续扩展、英雄之路或完整账号养成系统。
- 尚无官方英雄专属升级短片、语音、音效、可选棋盘与其他装饰系统；没有排位、匹配、观战或行动计时器。
- 联机房间没有玩家账户、房间自动清理和完整限流机制；刷新或恢复旧版对局时，如遇到状态版本不兼容，需要创建新房间。

## 验证与规则清单

GitHub Actions 在 push 和 pull request 时使用 Node.js 22 构建产物并运行验证与测试。

```sh
npm run build
npm run validate
npm test
npm run coverage
```

`npm run coverage` 从当前引擎的 `cardSupported` 和全部规则模块重新生成 `COVERAGE.md`，统计仅针对可收集卡牌，衍生记录另行说明。测试覆盖基础攻防与响应、英雄升级、生成牌与弃牌、随机候选池、多目标与献祭、捕获与复制、复活与进攻召唤、永久与临时增益，以及状态不可变性、隐藏信息、房间 API 和并发操作。实际断言和覆盖边界以 `tests/` 中的用例为准；卡牌清单不替代行为测试。

联机以服务端判定为准，客户端提交行动。数据库使用版本比较更新，避免重复提交或覆盖；返回给玩家的视图隐藏对手手牌、牌库内容与牌库顺序。

## 卡牌数据

```sh
node scripts/sync-cards.mjs
```

该脚本从官方 CDN 重新拉取固定 `7_10_0` 的 `en_us` 与 `zh_tw` Foundations JSON，生成 `src/cards.js`，并在 `DATASET` 中记录来源 URL 与原始数据的 SHA-256。美术由版本化的官方 CDN 图片链接加载，需要联网；仓库不包含图片文件。数据同步后应重新构建、测试并生成覆盖清单。

## 项目结构

- `src/cards.js`：生成的原版卡牌目录、数据来源、地区与预组套牌。
- `src/rules.js`、`src/advanced-rules.js`、`src/completion-rules.js`、`src/shadow-rules.js`：逐卡规则、英雄、牌库操作与复杂状态效果。
- `src/engine.js`：与 UI、网络和存储分离的规则引擎及玩家视图。
- `src/app.js`、`src/style.css`、`src/index.html`：牌桌、组牌器、图鉴与联机交互。
- `src/motion.js`、`src/motion.css`：公开结算事件、移动、法术、反馈与升级演出。
- `src/drag.js`、`src/drag.css`：鼠标和触屏拖拽、落点高亮、攻防连线。
- `worker/index.js`：服务端权威房间 API，使用 D1 接口。
- `drizzle/`：托管数据库迁移。
- `scripts/serve.mjs`：本地 Node HTTP 服务及 SQLite 适配器。
- `scripts/build.mjs`：生成包含规则、UI 和 API 的 Worker。
- `scripts/sync-cards.mjs`、`scripts/coverage.mjs`：数据同步与覆盖清单生成。
- `tests/`：规则与服务端集成测试。

## 自行部署

本地服务可部署到支持 Node.js 22.13+ 且提供持久化磁盘的主机。Cloudflare Worker 使用构建输出 `dist/server/index.js`，绑定名为 `DB` 的 D1 数据库，并先应用 `drizzle/0000_rooms.sql`。

Sites 托管资源由 `.openai/hosting.json` 声明。仓库只包含通用资源配置；自行部署时，在自己的账户中创建项目及数据库，并连接对应资源。数据库、座位凭证和部署项目标识不包含在源码仓库中。
